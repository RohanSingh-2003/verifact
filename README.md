## A. Project Introduction

### What is VeriFact?
**VeriFact** is an explainable, dual-engine hallucination detection and fact-verification system designed to evaluate whether answers generated by Large Language Models (LLMs) are factual, internally consistent, and backed by verifiable evidence.

Rather than relying on naive self-evaluation, VeriFact subjects an AI-generated answer to two independent evaluation engines:
1. **Engine A: MetaQA (Internal Metamorphic Consistency Engine)** — Evaluates whether the model's underlying knowledge state remains logically invariant when its statements are perturbed into meaning-preserving synonyms and meaning-reversing antonyms/negations, verified by a pool of independent cross-model verifiers.
2. **Engine B: Web Evidence (External Grounding Engine)** — Extracts atomic claims from the answer, routes domain-specific search queries through the Tavily Search API to authoritative sources, filters retrieved snippets for topical relevance, and verifies each claim against external documents.

An application-level synthesis layer then computes a **Combined Hallucination Risk** score while strictly preserving the independent research metrics.

---

### The Problem: Fact-Conflicting Hallucinations
Generative LLMs are trained to maximize token likelihood given prior context. While they produce fluent, coherent, and grammatically impeccable text, they frequently output **fact-conflicting hallucinations**—assertions that contradict real-world facts, historical records, scientific consensus, or established documentation.

In high-stakes domains such as medicine, law, engineering, and finance, undetected hallucinations can lead to critical failures, misinformation, and erroneous decision-making.

---

### Why Self-Reflection Fails
A common naive approach is "self-reflection": prompting the generator model to review its own output (*"Are you sure this answer is correct? Please check for mistakes."*). Research demonstrates that self-reflection systematically fails due to three fundamental issues:
- **Model Sycophancy & Confirmation Bias**: LLMs conditioned on their own generated tokens exhibit inflated confidence in their prior output.
- **Corrupted Latent Priors**: If an LLM's weights associate false entities (e.g., believing an event occurred in the wrong decade), prompting the same model merely samples from the same corrupted latent distribution.
- **Prompt Contamination**: Exposing the evaluator to the full original context cues the model to rationalize its prior reasoning rather than auditing the factual assertion objectively.

---

### What Makes VeriFact Different
- **Strict Generator Exclusion**: The model that writes the answer (**Gemma 4:26B**) is mathematically and architecturally prohibited from verifying its own answers or mutations.
- **Prompt Blindness**: Verifier models evaluate atomic propositions in isolation, without seeing the user prompt, original conversation, or expected outcome.
- **Orthogonal Dual-Engine Verification**: VeriFact tests both **internal cognitive consistency** (metamorphic logic) and **external empirical grounding** (live authoritative web retrieval).
- **Asynchronous Decoupled Execution**: The candidate answer is generated and delivered to the user immediately (`answer_ready`), while the intensive multi-model verification pipelines execute concurrently in the background.

---

### Key Capabilities
- **Instant Candidate Generation**: Generates responses in seconds via Gemma 4:26B on Ollama Cloud.
- **Automated Metamorphic Mutation**: Automatically parses answers into claims and generates 3 synonym and 3 antonym mutations.
- **Cross-Model Verifier Pool**: Concurrently queries Microsoft Phi-4 Reasoning, GLM-4.7-Flash, Qwen-2.5-32B, and Liquid LFM-2.5 under strict prompt blindness.
- **Direct-Answer Peer Review**: Concurrently obtains structured peer reviews (`Correct`, `Incorrect`, `Uncertain`) and synthesizes quorum consensus.
- **Authority-Aware Web Retrieval**: Categorizes questions into 8 domains and queries tier-1 sources (`.gov`, `.edu`, PubMed, Nature, Reuters) via Tavily Search with open web fallback.
- **Topical Relevance Filtering**: Applies a word-token overlap threshold ($\ge 0.20$) to purge noisy or irrelevant web search snippets.
- **Transparent Composite Scoring**: Visualizes individual claim verdicts, mutation penalties, Web Consistency Score, MetaQA Inconsistency Score, and Combined Hallucination Risk.

## C. System Architecture

VeriFact follows a clean, decoupled architecture:
- **Presentation Layer**: React 19 SPA built with TypeScript, Tailwind CSS v4, and Vite 8.
- **API Gateway & Orchestration**: FastAPI running on Python 3.10+ ASGI with Uvicorn.
- **Persistence Layer**: SQLite3 database (`verifact.db`) managed via SQLAlchemy 2.0 ORM.
- **Inference Layer**: Asynchronous HTTP clients connecting to Ollama Cloud, Hyperbolic, SiliconFlow, Groq, and DeepInfra.
- **Search Layer**: Tavily Search API client with domain whitelist filters and rate-limiting.

### Communication Flow
1. **Frontend Reverse Proxy**: In development, Vite (`http://localhost:5173`) proxies `/api` requests directly to FastAPI (`http://127.0.0.1:8000`), eliminating CORS complications.
2. **Immediate Handshake**: The user submits a question via `POST /api/detect/stream`. The backend generates the answer with Gemma 4:26B, stores the run with `status="RUNNING"`, and returns the base answer immediately.
3. **Background Dispatch**: FastAPI schedules verification pipelines as background tasks (`BackgroundTasks`).
4. **Reactive Polling**: The frontend hook `useVerificationPolling` polls `GET /api/runs/{id}` every 3,000 milliseconds.
5. **State Finalization**: Once background workers write the final scores, the run transitions to `status="COMPLETED"`, polling halts, and full scorecards render.

## E. AI/ML Concepts & Implementation

### 1. LLM-Based Answer Generation
- **Concept**: Generative sampling of token sequences from a frozen parameter distribution.
- **Why Used**: Provides candidate answers for factual analysis.
- **How Implemented**: Executed by **Gemma 4:26B** via the official Ollama Cloud API (`https://ollama.com/api`). Configured with `think: false` to suppress internal chain-of-thought tokens and keep latency low within a 350-token budget.

### 2. Hallucination Detection
- **Concept**: Automated classification of machine-generated text as factual or fabricated.
- **Why Used**: Generative models cannot reliably self-audit.
- **How Implemented**: Multi-branch pipeline combining internal consistency testing with external live web retrieval.

### 3. Metamorphic Testing (MetaQA)
- **Concept**: Software testing methodology for programs lacking an oracle (ground truth). It tests whether necessary relations (*metamorphic relations*) hold between multiple inputs and outputs.
- **Why Used**: Allows hallucination detection without requiring a pre-existing ground truth answer.
- **How Implemented**: If statement $A$ is asserted, its synonym paraphrasing $S(A)$ must also evaluate to true (`YES`), while its negation/antonym $N(A)$ must evaluate to false (`NO`). Contradictions violate metamorphic invariants.

### 4. Synonym and Antonym Mutations
- **Concept**: Semantic transformations preserving or inverting truth value.
- **Why Used**: Probes the boundary of the model's factual commitment.
- **How Implemented**: Gemma 4:26B produces 3 synonym and 3 antonym mutations bounded between 5 and 35 words using structured JSON prompts.

### 5. Prompt-Blind Multi-Model Verification
- **Concept**: Evaluating a proposition without exposing the evaluator to the original question or context.
- **Why Used**: Prevents context cues from biasing the verifier toward agreeing with the generated answer.
- **How Implemented**: Non-Gemma verifiers (Microsoft Phi-4, GLM-4.7-Flash, Qwen-2.5-32B, Liquid LFM-2.5) receive only the mutated proposition and return `YES`, `NO`, or `NOT SURE`.

### 6. Atomic Claim Extraction
- **Concept**: Splitting compound paragraphs into discrete, independently verifiable propositions.
- **Why Used**: Web search engines cannot verify complex multi-clause paragraphs effectively.
- **How Implemented**: Gemma 4:26B extracts up to 3 atomic claims with pronouns resolved into explicit named entities.

### 7. Authority-Aware Web Evidence Retrieval
- **Concept**: Grounding factual assertions in external documents using domain-tailored search.
- **Why Used**: Protects against model-wide shared training biases.
- **How Implemented**: Rule-based classifier maps queries to 8 domains. Tavily Search executes Pass 1 against official domain whitelists (`.gov`, `.edu`, PubMed, Nature, Reuters), falling back to open web search in Pass 2.

### 8. Topical Relevance Filtering
- **Concept**: Discarding irrelevant or noisy search snippets before verification.
- **Why Used**: Search engines often return navigation menus, cookie policies, or tangential news.
- **How Implemented**: Deterministic token overlap filter (`relevance.py`). Strips stopwords, tokenizes lowercase alphanumeric terms, and requires $\ge 0.20$ token overlap with the claim.

### 9. Compound-Claim Decomposition & NLI Evidence Classification
- **Concept**: Determining whether a premise text entails or contradicts a hypothesis.
- **Why Used**: Produces an objective verdict based strictly on retrieved text.
- **How Implemented**: Prompts an independent reasoning model (Phi-4) to evaluate entailment strictly against the retrieved snippet. If a compound claim has partial coverage, it is conservatively classified as `INSUFFICIENT_EVIDENCE`.

### 10. Score Calculation & Assessment Fusion
- **Concept**: Combining distinct verification signals into an interpretable metric.
- **Why Used**: Users need an executive verdict while researchers need raw independent scores.
- **How Implemented**: Deterministic Python functions compute the MetaQA Inconsistency Score (Equation 5), Web Consistency Score, and Combined Hallucination Risk ($0.5 \times \text{MetaQA} + 0.5 \times (1.0 - \text{WebScore})$).

### Primary REST Endpoints

  ```json

    "question": "Who discovered Penicillin and in what year?",

  }
  ```

- **Endpoint**: `GET /api/runs/{id}`
- **Purpose**: Polled by frontend every 3000ms. Returns full run state, mutations, claims, evidence, and scores.
- **Example Response (200 OK, Completed)**:
  ```json
  {
    "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
    "status": "COMPLETED",
  ```

## L. Scoring and Risk Assessment

### MetaQA Inconsistency Score (Equation 5)
For $N$ generated mutations ($N=6$ default: 3 synonyms, 3 antonyms), each mutation $m$ receives an observed verdict $v(m) \in \{\text{YES}, \text{NO}, \text{NOT SURE}\}$:

$$\text{Penalty}(m) = \begin{cases} 
0.0 & \text{if } \text{type}(m) = \text{synonym} \land v(m) = \text{YES} \\
1.0 & \text{if } \text{type}(m) = \text{synonym} \land v(m) = \text{NO} \\
0.5 & \text{if } \text{type}(m) = \text{synonym} \land v(m) = \text{NOT SURE} \\
0.0 & \text{if } \text{type}(m) = \text{antonym} \land v(m) = \text{NO} \\
1.0 & \text{if } \text{type}(m) = \text{antonym} \land v(m) = \text{YES} \\
0.5 & \text{if } \text{type}(m) = \text{antonym} \land v(m) = \text{NOT SURE}
\end{cases}$$

$$\text{MetaQA Score } H = \frac{1}{N} \sum_{i=1}^{N} \text{Penalty}(m_i) \quad \text{bounded in } [0.0, 1.0]$$

- **Threshold Classification** ($\theta = 0.50$):
  - $H < 0.50 \implies \textbf{Reliable}$
  - $H \ge 0.50 \implies \textbf{Hallucinated}$

---

### Web Evidence Consistency Score
For the set of eligible assessed claims $\mathcal{C}_{\text{assessed}}$:

$$V(c) = \begin{cases} 
1.0 & \text{if verdict} = \text{SUPPORTED} \\
0.5 & \text{if verdict} = \text{INSUFFICIENT\_EVIDENCE} \\
0.0 & \text{if verdict} = \text{CONTRADICTED}
\end{cases}$$

$$W = \frac{\sum_{c \in \mathcal{C}_{\text{assessed}}} V(c)}{|\mathcal{C}_{\text{assessed}}|}$$

*(Claims marked `NOT_ASSESSED_NO_RELEVANT_SOURCE` are excluded from the denominator. If no claims are eligible, $W = \text{None}$).*

---

### Combined Hallucination Risk Formula
$$\text{Web Risk} = 1.0 - W$$
$$\text{Combined Hallucination Risk} = 0.5 \times H_{\text{MetaQA}} + 0.5 \times \text{Web Risk}$$

---

### Categorical Verdict Matrix
- **`Likely Reliable`**: $H < 0.50$, $W \ge 0.85$, zero contradictory claims.
- **`Potentially Hallucinated`**: One or more claims `CONTRADICTED`, or $H \ge 0.50$.
- **`Needs Verification`**: Branch signals diverge (e.g., $H < 0.50$ but $W$ is low/insufficient).
- **`Insufficient Evidence`**: Web search inconclusive and MetaQA unavailable.
- **`Unavailable`**: Both verification pipelines were unconfigured or failed.

---

### Honest Theoretical Limitations
1. **Consistency $\ne$ Ground Truth**: Metamorphic testing verifies logical consistency. If an LLM firmly believes a popular myth (e.g., *"Lightning never strikes the same place twice"*), it will defend the myth across both synonym and antonym forms, scoring $H = 0.0$.
2. **Search API Boundaries**: Web Evidence depends on public internet retrieval via Tavily. Paywalled scientific journals, corporate intranets, or breaking real-time events may return no relevant sources.
3. **Heuristic Fusion**: The 0.5/0.5 weighting is an application engineering heuristic, not a trained statistical model.

## N. Limitations and Future Improvements

### Current Limitations
- **Fixed Generator**: Gemma 4:26B is permanently enforced; dynamic user model selection is disabled.
- **Lexical Relevance Filter**: The 0.20 token-overlap filter is lexical and may discard semantically relevant sources that use different technical synonyms.
- **Third-Party API Rate Limits**: High concurrency can trigger HTTP 429 rate limits on free-tier LLM and Tavily API keys.

### Known Implementation Issues
- `AnswerModelSelector.tsx` remains in the frontend codebase as dead code.
- In `backend/app/config.py`, `groq_model` defaults to `qwen-2.5-32b`, whereas `backend/app/llm/registry.py` defines `qwen/qwen3.8-27b`.
- The historical run in `experiments/results/58baff20...` used synthetic mock providers (`model-a`, `model-b`), not live commercial LLMs.

### Future Improvements
- Semantic embedding-based relevance filtering using small local sentence transformers.
- Dynamic selection of generator models with custom temperature controls.
- Integration of local offline LLMs (via Ollama local or llama.cpp) for air-gapped deployments.
- Machine-learned fusion weights trained on the 550-question benchmark.
